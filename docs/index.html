What is CORTEX?

A dynamic knowledge system that lives in .cortex/ and provides your AI agent with a complete, living map of your project.

map Living Knowledge Map

Every folder documented with a one-line purpose, one small file per folder. Agents look folders up with --find instead of loading the whole map.

autorenew Auto-Maintained

Renames and deletions reconcile themselves; the agent only describes new folders. No manual documentation upkeep required.

share Shared via Git

CORTEX files are normal project files. They appear in commits, pull requests, and code reviews. Knowledge travels with the repo.

extension Native Enforcement

Claude Code loads the knowledge through a rule file, hands subagents the lookup instructions via a SubagentStart hook, and a Stop hook blocks once per turn for new undescribed folders. OpenCode uses opencode.json instructions.

How It Works

Three steps to give your AI agent persistent project knowledge.

1
Install

Run a single curl command. CORTEX creates .cortex/, installs the knowledge layer, and configures your agent's native enforcement.

curl -sSL https://raw.githubusercontent.com/MaverickLBP/cortex/main/install.sh | bash

Or specify a path: bash install.sh /path/to/project

2
Build the map

Run /cortex-sync once. Every folder is described by one agent and verified by a second one against its real contents; large projects are split across parallel subagents.

/cortex-sync

Claude Code and OpenCode — same command

3
Stay in sync

While you work, the agent finds folders with cortex-map.sh --find and the map reconciles as folders are added, renamed or removed. Run /cortex-sync after changes made outside a session — a git pull, folders created by hand, a branch switch.

/cortex-sync

Commands

One command to reconcile your project's knowledge layer.

sync cortex-sync

Reconciles the folder map and PROJECT.md with what is actually on disk. Idempotent: on a fresh project everything is missing, so it generates the whole map; on a mature one it only closes the gaps — describes folders that appeared, drops folders that are gone, refreshes the Tech Stack table, and deduces Conventions the first time. Each description comes from the folder's real contents through a work queue (cortex-describe.sh) and is verified by a second agent; the sync only finishes when every folder is verified. There is no separate initialization command.

Claude Code: /cortex-sync
OpenCode: /cortex-sync

Compatibility

Native, guaranteed enforcement for Claude Code and OpenCode.

Agent Support Notes
Claude Code rule file, SubagentStart & Stop hooks + slash command (/cortex-sync)
OpenCode opencode.json auto-loads the knowledge files at session start + slash command (/cortex-sync); no hooks, so map maintenance is followed by instruction alone

Installation

One command to add CORTEX to any project.

Quick Install
curl -sSL https://raw.githubusercontent.com/MaverickLBP/cortex/main/install.sh | bash

Or install to a specific directory:

curl -sSL https://raw.githubusercontent.com/MaverickLBP/cortex/main/install.sh | bash -s -- /path/to/project
After Installing

Works the same in Claude Code and OpenCode:

  1. Start a new session with your agent
  2. Run /cortex-sync once to generate the map; after that, on Claude Code the Stop hook asks the agent to describe any new folder at the end of a turn
  3. Run /cortex-sync to reconcile the map after changes made outside a session — a git pull, folders created by hand, a branch switch
